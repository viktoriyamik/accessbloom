01 / THE OPPORTUNITY

Accessibility findings are only useful when teams know what to do with them.

Accessibility tools often return long technical lists. A designer may know that a contrast rule failed without understanding the user impact or the right remediation path. AI can help bridge that gap, but only when its explanations are grounded in verifiable evidence.

Design question: How might we translate technical accessibility checks into trustworthy, understandable actions without overstating what AI can verify?

02 / THE APPROACH

From detection to informed action.

01

Capture evidence

Playwright renders a permitted page. axe-core detects rule violations and identifies affected selectors.

02

Explain with AI

A multimodal model receives bounded evidence, HTML excerpts, and optional screenshot context to propose fixes.

03

Validate with humans

Reviewers inspect code suggestions, record decisions, and compare subsequent assessments.

03 / PRODUCT DECISIONS

AI should support judgment, not replace it.

AccessBloom distinguishes automated facts from generated suggestions. Critical issues are prioritized, with their affected element and rule evidence attached. Recommendations are labelled as AI-generated when an API is configured.

The interface makes uncertainty visible: a score is a prioritization heuristic, not a measure of WCAG compliance. A review checklist reminds users to evaluate keyboard access, screen readers and real human journeys.

05 / WHAT WAS BUILT

An interactive accessibility review workspace.

  • Publicly explorable sample audit with five realistic issue types.
  • Owner-controlled, allowlisted single-page scans on a server with Playwright and axe-core.
  • Optional evidence-grounded multimodal AI remediation summaries.
  • Issue details, HTML evidence, improvement suggestions and reviewer notes.
  • History, before-and-after comparison, JSON/CSV exports and print-to-PDF.
  • Backend tests, security controls, reproducible Ubuntu deployment files and documentation.

Validation status and limitations are intentionally explicit. No user-research metrics or accessibility compliance outcomes are invented.

06 / NEXT ITERATION

What I would validate next

Observe designers and developers using the product, compare AI recommendations against expert-reviewed fixes, assess trust and comprehension, and test how issue grouping supports complex websites. Future releases could add multi-page projects, team access, and more systematic human-AI evaluation.
